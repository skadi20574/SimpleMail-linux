# SimpleMail

一个本地优先（local-first）的开源 Linux 桌面邮件客户端（MIT 许可），界面与操作习惯参照
Foxmail，但完全独立实现，不使用任何商业软件的商标、图标、素材或代码。

特点：

1. **邮件留在本机**。所有同步下来的邮件（正文、头部、附件元数据）都写进本地
   SQLite，附件单独落盘，没有自动清理逻辑，断网可读、搜。
2. **能读以前的 Foxmail 存档**。新版 Foxmail 7.2 的 `.fox` 单文件存档、老版本的
   `mail/账户/*.box + .ind`、整个 Foxmail 数据目录，甚至打包成 `.zip` 的以上任意一种，
   都**自动识别、不需要你选版本**；导出时也会同时产出 `.fox` / `.box+.ind` /
   `.eml` / `.mbox` 四种格式。

## 技术选型

**Electron 38 + TypeScript + React 18 + Vite**，数据库用 **Electron 内置 Node 22 的
`node:sqlite`**（SQLite 3.50.4，编译时已启用 FTS5）。

### 为什么不是 Tauri

需求里先提到 Tauri + Rust。实际评估后选了 Electron，原因都是可验证的：

| 维度 | Tauri + Rust | Electron 38（本次选择） |
| --- | --- | --- |
| 构建机工具链 | 需要 rustup + cargo（约 1.5 GB），本机原本没有 | 只需 Node.js |
| 依赖源 | crates.io 在当前网络下直连返回 403 | npm registry / 镜像均正常 |
| 产物体积 | 约 10–20 MB（优势明显） | 约 90 MB |
| **跨机器兼容性** | 需要在本机把 Rust 依赖**编译**进去，会绑死构建机的 glibc（本机是 26.04 / glibc 2.43），在 22.04 上反而更容易出问题 | 运行时由 Electron 官方预编译，只要 glibc ≥ 2.31（Ubuntu 20.04+）即可 |
| 原生模块 | 无 | **无** —— 见下 |

最后一条是关键：**这个项目里没有任何原生模块需要编译**。

通常 Electron 项目要用 `better-sqlite3`，那是 C++ 原生模块，得针对 Electron 的 ABI
重新编译，产物会引用构建机的 glibc 符号版本 —— 在 Ubuntu 26.04 上打出来的包，拿到
22.04 上就可能因为 `GLIBC_2.4x not found` 起不来。

这里改用 Electron 38 内置的 `node:sqlite`：

```js
const { DatabaseSync } = require('node:sqlite')   // Node 22.20 自带
db.exec("CREATE VIRTUAL TABLE t USING fts5(x)")   // FTS5 可用
```

于是：

- 不需要 `electron-rebuild`，不需要 `node-gyp`，不需要 python/g++ 编译环境；
- 安装包里只有 JS，**不绑死构建机的 glibc**；
- 打包配置里干脆写死了 `npmRebuild: false`。

代价是 `node:sqlite` 目前还带「实验性」标记（会打印一条警告，程序里已静音）。
数据库访问全部集中在 `src/main/db/sqlite.ts` 一个文件里，将来若要换回
`better-sqlite3`，只需要改这一个文件。

### 为什么 POP3 自己写而不引库

POP3 是极简单的行协议（RFC 1939），但有几个「看起来能跑、接真机就出错」的细节，
交给不透明的库反而不好控制，所以 `src/main/mail/pop3.ts` 里自己实现（约 400 行）：

| 细节 | 不处理会怎样 |
| --- | --- |
| **点填充（dot-stuffing）** | 正文里以 `.` 开头的行在传输时被写成 `..`，还原错了邮件内容就会多一个点或多一截 |
| **多行响应以单独一行 `.` 结束** | 没有正确的结束判定，长邮件会被截断或多读 |
| **字节透明** | 全程按 Buffer 处理，绝不经 UTF-8 字符串中转，否则中文和二进制附件会被破坏 |
| **DELE 只在 QUIT 时生效** | 不发 QUIT 就断开，服务器会回滚全部删除标记 —— 反过来说，中断时天然不会误删 |
| **UIDL 是可选的** | 服务器不支持时要退化为「全量下载 + 按 Message-ID 去重」，否则永远重复下载 |
| **隐式 TLS 与 STLS 两条路** | 995 是隐式 TLS，110 需要 STLS 升级，两者握手前的 socket 状态不同 |

这些行为都用本地 mock POP3 服务器做了端到端验证（含点填充、隐式 TLS、STLS 升级、
删除提交语义、中断不删），见下文「自检与测试」。

### 其他依赖

| 用途 | 选择 | 说明 |
| --- | --- | --- |
| IMAP | `imapflow` | 纯 JS、Promise API、支持 UID 增量同步 |
| POP3 | **自己实现** | 原因见上文「为什么 POP3 自己写而不引库」 |
| SMTP | `nodemailer` | 事实标准 |
| MIME 解析 | `mailparser` | 处理 RFC2047 编码字、multipart、附件 |
| 编码兜底 | `iconv-lite` | 国内老邮件大量使用 GB2312/GBK，必需 |

## 快速开始

### 环境要求

- 开发机：Ubuntu 22.04 / 24.04 / 26.04，Node.js 20+
- 运行机：同上，只要 glibc ≥ 2.31

### 开发调试

```bash
git clone <本项目>
cd simplemail
npm install          # 大陆网络建议先看 scripts/build.sh 里的镜像设置
npm run dev          # 带热更新的开发模式
```

### 构建安装包

```bash
./scripts/build.sh                 # 类型检查 + 自检 + 打包三种形态
./scripts/build.sh --no-test       # 跳过自检，快一些
USE_MIRROR=0 ./scripts/build.sh    # 网络能直连 GitHub 时关掉镜像
```

产物在 `release/`：

```
SimpleMail_1.0.0_amd64.deb                  # 双击 / dpkg -i 安装
SimpleMail-1.0.0-x86_64.AppImage            # 单文件，chmod +x 后直接跑
simplemail-1.0.0.tar.gz                     # 解压即用，不依赖 FUSE
```

安装与使用的详细说明见 **[docs/INSTALL.md](docs/INSTALL.md)**。

> ⚠️ 关于 AppImage：Ubuntu 22.04 之后默认不再安装 `libfuse2`，AppImage 会提示
> `dlopen(): error loading libfuse.so.2`。这**不是包坏了**，装一下即可：
> `sudo apt install libfuse2`（22.04）或 `sudo apt install libfuse2t64`（24.04+），
> 或者直接改用 `tar.gz` 便携版 / `.deb`。
> 详见 [docs/INSTALL.md](docs/INSTALL.md#appimage-提示-libfuse2-缺失)。

## 文件夹管理

左侧的文件夹可以像文件管理器一样管理。**右键任意文件夹**弹出原生菜单：

```
在此文件夹下新建子文件夹…
新建同级文件夹…
─────────
重命名…
删除文件夹（含 N 封邮件）
─────────
账户：立即同步
```

账户名右侧也有一个 **＋** 按钮，直接在账户根下新建文件夹。

### 新建与重命名

文件夹名会按账户的层级分隔符拼成路径：给了父文件夹就是 `父路径/名字`，否则是顶层名字。

**IMAP 账户会同时在服务器上创建 / 重命名对应的 mailbox**，手机端也能看到同一个文件夹树。
本地存档账户与 POP3 账户只有本地文件夹（协议本身没有服务器文件夹概念）。

重命名时**路径会一起更新**——不更新的话，下次同步会按路径匹配到一个「新」文件夹，
把一份邮件散成两份。

### 删除文件夹

删文件夹时会先问里面的邮件怎么处理：

| 选择 | 结果 |
| --- | --- |
| **移到垃圾箱**（默认推荐） | 邮件保留在本机垃圾箱，可随时找回 |
| **连同邮件永久删除** | 本机数据库记录 + 磁盘附件文件一并清掉，不可恢复 |

IMAP 账户会同时删除服务器上的文件夹。**顺序很关键**：先把邮件搬到垃圾箱、
再删 mailbox —— 反过来的话 `mailboxDelete` 会连同邮件一起删掉，就找不回来了。

**收件箱不能删除也不能重命名**：它是 IMAP 同步的锚点，改名会让同步逻辑找不到入口。

### 拖拽归类

在邮件列表里按住一封邮件拖到左侧任意文件夹上松手即可移动（该文件夹会高亮）。
拖动的是**已选中的邮件**：如果拖的那封在多选范围内，整批一起走；否则只拖这一封。
如果只想移动一封，先点空白处取消选择即可。

## 搜索、右键菜单与读信

### 按字段专项搜索

点搜索框右边的漏斗按钮（**字段**）展开一排**并列的输入框**：

```
[ 发件人 ]  [ 收件人 ]  [ 主题 ]  [ 正文 ]
```

每个框都可以留空 —— **留空即不限定**；填了多个就是**同时满足**（AND）。
比如「发件人 = 张三」且「主题 = 合同」，只会列出两条都符合的邮件，
而不是各自命中的并集。工具栏那个通用搜索框在**全部字段**里匹配，可以和它们叠加使用。

限定字段能生效，是因为索引里每个字段各存了一列逐字 CJK 数据
（`cjk_subject` / `cjk_sender` / `cjk_recipients` / `cjk_body`），
所以「发件人 + 张三」这种查询是真的只在发件人字段里找，不会把正文里提到"张三"的邮件也捞出来。

### 匹配度排序

搜索时结果**默认按相关度排序**，用的是 SQLite FTS5 的 `bm25()`：
词频高、文档短的排前面。列表头会出现一个「相关度」按钮，点「时间 / 主题 / 发件人」
可以切回常规排序，再点「相关度」切回来。
（实测 contentless 的 FTS5 表同样支持 `bm25()` —— 它只需要索引里的词频与文档长度。）

### 右键菜单

在邮件列表上右键会弹出**系统原生菜单**（位置、键盘导航、点外部关闭都由系统处理）：

```
在新窗口打开
─────────
标记为已读 / 标记为未读
加星标 / 取消星标
─────────
回复 / 回复全部 / 转发
─────────
移动到 ▸（子菜单，按当前账户的文件夹列出）
─────────
移到垃圾箱
永久删除
```

菜单项会根据选择状态动态变化（比如全是已读时显示「标记为未读」）。
多选时菜单文字后面会带上「（N 封）」。右键点在没被选中的行上时，
会先把它变成当前选择 —— 和文件管理器一致。

### 已读 / 未读标记

邮件行最左边是三格固定占位，互不顶替：

| 格子 | 显示 |
| --- | --- |
| 第一格 | **未读 = 绿色圆点**；**已读 = 灰色小对勾**（两种状态都有标记，一眼可辨） |
| 第二格 | 已加星标时显示橙色五角星 |
| 第三格 | 复选框，未悬停时隐藏但保留占位，所以文字不会左右跳 |

**打开邮件是否自动标记已读**可以在「设置 → 常规」里关掉。关掉之后需要自己改状态：
右键菜单里有「标记为已读」和「标记为未读」两项（两个方向都在，多选状态混杂时也能用），
或者按 `M` 键切换。

### 双击开独立窗口

双击邮件会在一个新窗口里打开它，方便一边看别的邮件一边读这一封。
同一封邮件重复双击只会聚焦已有窗口，不会开出好几个。窗口里按 `Esc` 关闭。

独立窗口和主窗口共用同一个正文渲染组件，所以沙箱 iframe、默认阻止远程图片
这些安全策略完全一致。

## 主题

支持**浅色 / 深色 / 跟随系统**三种模式，工具栏上有一个切换按钮，图标就是：

| 图标 | 模式 |
| --- | --- |
| 小太阳 | 浅色 |
| 月亮 | 深色 |
| 半明半暗的圆 | 跟随系统 |

「设置 → 常规 → 界面主题」里也可以直接选。

实现上分了工：主进程把模式写进 Electron 的 `nativeTheme.themeSource`
（这样「跟随系统」由 Chromium 负责），渲染层只监听 `prefers-color-scheme` 的变化、
在 `<html>` 上打 `data-theme`，CSS 变量随之切换 —— 所以跟随系统时**不需要任何 IPC 往返**。

界面里的全部颜色都走 CSS 变量（60 多个），没有硬编码的浅色值，深色下不会出现"白块"。

## 图标

界面上的图标全部是**自己画的线条 SVG**（`src/renderer/src/components/Icon.tsx`，
29 个图标，统一 16×16 视图、`currentColor` 描边）。

原来用的是 emoji，有两个问题：emoji 是彩色位图字体，不同系统/字体下字形差异很大；
而且它不跟随文字颜色、不能调粗细，和浅色界面完全不搭。线条图标两个问题都没有。

## 自动归类与自动删除规则

工具栏「**规则**」按钮打开。规则在邮件**落地时自动执行** ——
无论是 IMAP/POP3 同步下来的新邮件，还是导入的 Foxmail 存档。

### 条件

| 字段 | 说明 |
| --- | --- |
| 发件人地址 / 发件人姓名 | 最常用的归类依据 |
| 收件人 / 抄送 | 按收件地址分流（比如发给某个邮件列表的） |
| 主题 / 正文 | 关键词过滤 |
| **指定邮件头** | 匹配任意自定义字段，写成 `List-Id: dev.lists`、`X-Spam-Flag: YES` 这样 |
| 任意字段 | 上面所有字段合并匹配 |

操作符：包含 / 不包含 / 等于 / 开头是 / 结尾是 / **匹配正则**。
多条条件可以选择「满足全部」或「满足任一」。

### 动作

移动到指定文件夹 / 移到垃圾箱 / **永久删除** / 标记已读 / 加星标 / 标记已读并移动。

### 三个关键设计

**1. 依赖正文的规则会推迟评估。** 同步是先抓信封、再补正文的两段式。
只用邮件头就能判断的规则（比如按发件人）在邮件出现在列表的瞬间就生效；
需要看正文的规则会等正文下载完再补评一次。所以**「同步时补齐正文」这个选项要开着**，
否则正文类规则永远不会命中。

**2. 同一条规则对同一封邮件只执行一次。** 这不是优化而是正确性要求：
正文补下来后规则会重评一次，如果规则是「移到垃圾箱」，第二次执行时邮件已经在垃圾箱里，
而"Delete 垃圾箱里的邮件"的语义是永久删除 —— 会误删。所以每封邮件会记录
已经执行过动作的规则 id。

**3. 删除类动作会同步到 IMAP 服务器。** 只删本地的话下次同步邮件又回来了。
（POP3 与本地存档账户没有服务器文件夹，就是纯本机处理。）

### 试运行

规则编辑器里有「**试运行（不改数据）**」按钮：拿现有邮件跑一遍条件，
告诉你最近 500 封里有多少封命中、并列出前 20 封样例。
写「永久删除」这类危险规则前**强烈建议先跑一次**。

「对现有邮件套用一遍」按钮则是对**还没被规则处理过**的邮件执行全部启用规则 ——
新建的规则会自动应用到老邮件上，但已经处理过的不会重复执行。

## Foxmail 存档兼容

这是本项目的重点，单独成篇：**[docs/FOXMAIL.md](docs/FOXMAIL.md)**。

一句话概括：**不猜格式，而是把邮件「抠」出来**。

Foxmail 的存档格式跨版本差异很大，而且 7.2 的 `.fox` 容器没有公开规范。与其为每个
版本写一个脆弱的解析器，本项目采用「只要能定位到原始 RFC822 报文就能导入」的策略，
按可靠性从高到低依次尝试五条线索：

1. Foxmail 报文分隔符（16 字节 `10×7 11×6 53 0D 0A`）—— `.box` 的主路径；
2. 行首邮件头（`Return-Path:` / `Received:` / `Message-ID:` …）+ 头部块合法性校验
   —— 用于容器未知的 `.fox`；
3. mbox 的 `From ` 分隔行；
4. 内嵌的 ZIP 局部文件头；
5. 内嵌的 zlib / raw-deflate 压缩流。

任何一条成功即可完成导入，因此**新旧版本自动兼容**。

另外，对老版本的 `.ind` 索引做**自标定**：拿索引里的候选取值和 `.box` 中真实的分隔符
位置比对，哪个「记录长度 + 字段位置」组合能对上就用哪个。识别成功后会把布局记进
数据库，导出时按**同一套布局**写回去 —— 这就是「导出成同样格式」的实现方式。

## 卸载

程序里就能卸载：「**设置 → 关于 → 卸载**」会检测当前的安装方式：

| 安装方式 | 界面上的行为 |
| --- | --- |
| `.deb` | 「卸载 SimpleMail」按钮 → 弹出系统授权对话框 → 执行 `apt-get remove simplemail` |
| AppImage | 显示文件路径与命令，退出后自行删除该文件 |
| 便携版（tar.gz） | 显示目录路径与命令，退出后自行删除该目录 |

用 `pkexec` + `apt-get remove` 而不是直接删 `/opt` 下的文件，是因为后者会让 dpkg
数据库里留下记录，变成「半卸载」的坏状态。

**卸载不会删除你的邮件**。要一并清理，用同一个页面里的「清除本地数据」
（会要求手动输入 `DELETE` 确认，然后删除数据库、附件目录与导出目录并重启）。

## 已知限制

- **草稿只存本地**，不会同步到服务器的 Drafts 文件夹（避免覆盖服务器草稿造成数据丢失）。
- **POP3 账户只有收件箱来自服务器**。「已发送 / 草稿箱 / 垃圾箱」是纯本地文件夹，
  且没有已读状态回写（POP3 协议本身不支持）。发信仍走 SMTP。
- **不支持 OAuth**。Outlook/Office365 强制现代验证的账户用密码登录不了；QQ、163 等
  使用授权码的账户正常。
- **`.fox` 是闭源私有格式**，本项目通过报文雕刻做到「能读」，但：
  - 若某个版本的 `.fox` 对邮件体做了加密或自研压缩，雕刻可能读不出来；
  - 项目的「存档体检」（导入/导出对话框 → 存档体检）会把文件头、识别结果、每个
    文件夹扫描到的邮件数与所用策略列成报告，遇到读不出来的文件请把报告保留下来。
- **Foxmail 反向兼容有限**。`.box` / `.ind` 的结构是按公开资料与自标定实现的，
  不保证能被 Foxmail 原样识别；因此导出时**默认同时产出** `.eml` 与 `.mbox`，
  这两个格式 Foxmail 可以直接导入。
- 邮件正文的远程图片默认**阻止加载**（防跟踪像素），阅读时可临时放行。
- 双击 `.deb` 时软件中心显示的描述来自 **AppStream 元数据**
  （`build/linux/simplemail.metainfo.xml`）。如果没有这份元数据，GNOME 软件中心会
  回退到 deb control 的 Description，而那条回退链路上非 ASCII 字符会变成「?」。
  所以包里的 `synopsis` / `description` 写成英文，中文描述由 AppStream 与
  `.desktop` 的 `Comment[zh_CN]` 提供。
- **自动规则里的「永久删除」没有二次确认**（规则本来就是无人值守的）。
  配置时请务必先用「试运行」确认条件写对了。
- 依赖正文的自动规则需要正文已经下载到本地。如果关掉了「同步时后台补齐正文」，
  这类规则要等你在阅读时触发正文下载之后才会生效。
